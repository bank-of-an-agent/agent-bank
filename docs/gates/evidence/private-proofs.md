# Private proofs evidence: end to end

What it shows ([design](../../private-proofs.md), ADR 0014): agents prove **agent credentials**, **private reputation** and **proof of funds / reservations** to sellers with real Groth16 proofs, without revealing which agent they are; owners control what may be disclosed, and narrowing, freezing and early releases revoke roots at once.

**Result: PASS.** 9 of 9 scenarios ran end to end. 26 proofs generated, 23 presentations accepted by the sellers' gates, 7 refused by the gates and 12 requests refused by the agent's own SDK before proving. 23 roots built, 20 revoked (20 revoked in the registry on-chain), 0 failed.

The whole stack runs in one process over real HTTP (API, co-signer, reconciler, indexer, x402 facilitator, the real `proofs-roots` and `proofs-reservations` jobs) on the simulated chain, whose `AgentAttestationRegistry` anchors every root. Agents use the TypeScript SDK (`agent.proofs`, `fetchWithPayment`), owners the `PrincipalClient`, and two sellers admit agents with `@agentbank/sdk/proof-server` gates that resolve roots through `GET /v1/proofs/roots/{root}`. Generated by `tests/e2e/test/private-proofs.test.ts`; reproduce with `pnpm --filter @agentbank/e2e gate:proofs` (this file is rewritten only then; CI's `pnpm test` runs the same suite with fewer timing runs).

Runtime 69.0 s on linux x64, 22 CPUs. Circuit `agent_claims`: 10,270 constraints, Groth16 on BN254, keys from the single-party testnet-only setup.

## Scenarios

|     | Scenario                       | Checked                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| --- | ------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| a   | Agent credentials              | Owner-signed widening (unsigned: `owner_signature_required`); root valid in the registry; `verifiedCompany() + canPayPerTx(1.00)` → 200; the presentation carries no account, agent, org, address or commitment; nullifier stable per seller, different across sellers                                                                                                                                                                                    |
| a   | Agent credentials (individual) | An individual's agent is refused by its own SDK (`unsatisfiable`, `principal_verification`) before proving; the seller sees only its challenge                                                                                                                                                                                                                                                                                                            |
| a   | Anonymity set                  | A root of 3 leaves satisfies `min_anonymity_set = 3`; one more is refused with `anonymity_set_too_small`                                                                                                                                                                                                                                                                                                                                                  |
| b   | Private reputation             | 2 settled payments, an escrow released to the agent, a dispute resolved in its favour; `reputation({ escrowsCompleted: 1, disputesLostAtMost: 0, paymentsSettled: 2 }) + accountOlderThan(0)` → 200; over-claims (2 escrows, 3 payments, 30 days) and the losing party's clean-record claim refused (`unsatisfiable`)                                                                                                                                     |
| c   | Proof of funds                 | $150.75 funded: `balanceAtLeast(150.00)` → 200, `150.75` refused (whole dollars); $25 reserved for seller A (available −$25, `reservation_pending` until the next root) proves `reservedFor(25.00, 10 min)` to A only (B: `reservation_required`); owner release voids the hold, revokes every root holding it (API and registry) and a prepared presentation gets `root_revoked`; a 90 s reservation expires with the world clock and its hold is voided |
| d   | Disclosure control (narrowing) | Removing `balance` with the API key alone: no witness is served before the new root (`proof_not_ready`), the wider roots are revoked (API and registry, `root_revoked` at the gate), a balance proof is refused (`undisclosed`), credentials still prove                                                                                                                                                                                                  |
| d   | Disclosure control (freeze)    | Freezing the agent publishes a root without it, revokes the older roots (API and registry; `root_revoked` at the gate) and its witness is refused (`agent_frozen`)                                                                                                                                                                                                                                                                                        |
| e   | Proof + payment                | `fetchWithPayment` answers 401 (proof) then 402 (x402 $0.05) in one call; one proof, the same `AGENT-PROOF` on the paid retry; settled; ledger and reconciliation invariants hold                                                                                                                                                                                                                                                                         |
| f   | Replay and tampering           | Replayed `AGENT-PROOF` → `nonce_reused`; a loosened bound → `nonce_invalid`; relayed to another seller → `nonce_invalid`; `POST /v1/proofs/verify`: original valid, altered request `request_hash_mismatch`, re-hashed `invalid_proof`, forged nullifier `invalid_proof`                                                                                                                                                                                  |

## Timings

| Step                                                |   n |     Min |  Median |     p95 |     Max |
| --------------------------------------------------- | --: | ------: | ------: | ------: | ------: |
| Proving (Groth16, witness in hand)                  |  26 | 1281 ms | 1569 ms | 1698 ms | 1705 ms |
| Gate check (root lookup over HTTP + Groth16 verify) |  30 |  0.4 ms | 99.7 ms |  141 ms |  172 ms |

Proving runs in the test process alongside the whole stack, so it is slower than on an idle machine (the design quotes about 1.3 s); refused gate checks that stop before the pairing check (nonce, root) are the fast tail.

## Anonymity sets

| Quantity                                       |   Value |
| ---------------------------------------------- | ------: |
| Leaves of the roots proved against (min – max) |   2 – 8 |
| Distinct roots proved against                  |       9 |
| Sellers' default `min_anonymity_set`           |       2 |
| `min_anonymity_set` values requested           | 2, 3, 4 |

The stack has a handful of agents, so the sellers lower `min_anonymity_set` to 2 (the SDK default, and the bar for real deployments, is 16). The boundary scenario asks for exactly the tree's leaf count (accepted) and one more (`anonymity_set_too_small`).
