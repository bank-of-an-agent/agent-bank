# Architecture decisions

Significant choices are recorded as architecture decision records (ADRs) in [`docs/adr/`](https://github.com/bank-of-an-agent/agent-bank/tree/main/docs/adr): short documents with the context, the decision and its consequences. Superseded records stay, marked as such. All of the records below are accepted.

| ADR                                                                                                          | Decision                                                                                              | Why it matters                                                                                                                                                                                                                                                                                                                                                                        |
| ------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [0001](https://github.com/bank-of-an-agent/agent-bank/blob/main/docs/adr/0001-x402-spend-key-float.md)       | x402 payments are signed by a per-agent **spend key** holding a small USDC float                      | The Phase 0 spike showed that a Safe's ERC-1271 signature can authorize EIP-3009 transfers outside every on-chain cap, and an undeployed Safe cannot sign at all. A spend key bounds a compromised agent to its float, refills go through the full policy stack, and a permit lets the owner sweep the float back. See [Accounts and keys](/concepts/accounts-and-keys#the-spend-key) |
| [0002](https://github.com/bank-of-an-agent/agent-bank/blob/main/docs/adr/0002-repository-structure.md)       | One platform monorepo, plus separate repositories for the contracts, the Python SDK and the exit tool | Contracts are audited and frozen as a unit, the Python SDK has its own toolchain, and the exit tool must be visibly independent of Agent Bank                                                                                                                                                                                                                                         |
| [0003](https://github.com/bank-of-an-agent/agent-bank/blob/main/docs/adr/0003-api-contract-single-source.md) | The Zod route registry in `@agentbank/core` is the single source of truth for the API                 | The server, the TypeScript SDK, `docs/openapi.json` and this [API reference](/api/) are all derived from it; CI fails on a stale document                                                                                                                                                                                                                                             |
| [0004](https://github.com/bank-of-an-agent/agent-bank/blob/main/docs/adr/0004-sql-client-pglite.md)          | One `SqlClient` over node-postgres and PGlite                                                         | Database tests run in-process on PGlite and on PostgreSQL 16 in CI; money is never a JavaScript number                                                                                                                                                                                                                                                                                |
| [0005](https://github.com/bank-of-an-agent/agent-bank/blob/main/docs/adr/0005-owner-operations.md)           | Owner-only on-chain actions are first-class **owner operations**                                      | One flow and one signing UI for installing sessions, configuring executors, early vault withdrawals and `require_owner` payments. See [Owner operations](/concepts/owner-operations)                                                                                                                                                                                                  |
| [0006](https://github.com/bank-of-an-agent/agent-bank/blob/main/docs/adr/0006-ap2-mandates.md)               | Mandates use the AP2 v0.2 open Payment Mandate claims, signed with an EIP-712 owner authorization     | Auditors can verify the owner's signature over the exact mandate; an SD-JWT envelope is an encoding change for later. See [Mandates](/concepts/mandates)                                                                                                                                                                                                                              |
| [0007](https://github.com/bank-of-an-agent/agent-bank/blob/main/docs/adr/0007-agent-request-signatures.md)   | Agents authenticate with RFC 9421 signatures using `eip191-secp256k1`                                 | One key per agent session for HTTP and on-chain authority; shared test vectors keep the SDKs identical. See [Request signing](/guides/request-signing)                                                                                                                                                                                                                                |
| [0008](https://github.com/bank-of-an-agent/agent-bank/blob/main/docs/adr/0008-fee-collection.md)             | Fees are batched into the payer's own operation, or accrued and swept; Agent Bank never pulls funds   | No allowance or bank key can take funds, which keeps the non-custodial line. See [Fees and plans](/concepts/fees-and-plans)                                                                                                                                                                                                                                                           |
| [0009](https://github.com/bank-of-an-agent/agent-bank/blob/main/docs/adr/0009-keeper-executors.md)           | Auto top-up and the treasury sweep run as owner-installed executor modules that anyone may trigger    | Triggering is not a privileged power: executors move funds only between the org's own accounts or to the one fund the owner chose                                                                                                                                                                                                                                                     |
| [0010](https://github.com/bank-of-an-agent/agent-bank/blob/main/docs/adr/0010-rolling-policy-windows.md)     | Policy limits use rolling windows (24 hours, 7 days, 30 days)                                         | Calendar windows would allow twice the daily cap across midnight; the on-chain hook's UTC days are always looser, so the off-chain engine is the tighter layer                                                                                                                                                                                                                        |
| [0011](https://github.com/bank-of-an-agent/agent-bank/blob/main/docs/adr/0011-indexer-on-chain-gateway.md)   | The indexer polls through `ChainGateway` instead of Ponder                                            | One code path for simulation and Base Sepolia; a compromised indexer can delay evidence but cannot write arbitrary ledger entries. See [Reconciliation](/concepts/reconciliation)                                                                                                                                                                                                     |
| [0012](https://github.com/bank-of-an-agent/agent-bank/blob/main/docs/adr/0012-approval-attestation.md)       | In v1 the co-signer trusts approvals attested by the API (a known limitation)                         | A compromised API could approve payments that need approval but cannot exceed hard caps; the follow-up is verifying passkey assertions in the co-signer                                                                                                                                                                                                                               |
| [0013](https://github.com/bank-of-an-agent/agent-bank/blob/main/docs/adr/0013-guardian-recovery.md)          | Guardian recovery uses Candide's audited `SocialRecoveryModule`, 72-hour variant                      | No custom recovery contract to audit; the owner can cancel during the delay, and provisioning keeps Agent Bank to at most one guardian seat, never a majority. See [Recovery](/concepts/accounts-and-keys#recovery)                                                                                                                                                                   |

To propose a decision, add the next numbered file to `docs/adr/` with the same three sections and list it in the index.
